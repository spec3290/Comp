### 수용 기준

**F1-6 소셜 로그인**
- Google, Kakao OAuth2만 지원한다. ID·비밀번호 가입/로그인은 만들지 않는다 (ADR-0003).
- 최초 로그인 시 `provider + providerId`로 회원을 자동 생성하고, 이후에는 같은 키로 기존 회원을 조회한다.
- 성공하면 서비스 자체 JWT(Access/Refresh)를 발급한다 (F1-4).
- 신규 회원은 프로필 미설정 상태임을 응답으로 알 수 있어야 한다. (가정: `needs_onboarding`)
- 진행: Google 완료(2026-10-26 실제 계정으로 가입·재로그인 확인). 2026-10-28 콜백을 프론트 리다이렉트 + 일회용 코드 교환으로 변경(Q-16). Kakao는 남음.

**F1-7 프로필 설정**
- 입력: 닉네임, 학년, 학교 유형, 관심 분야. 최초 OAuth 로그인 직후 온보딩에서 받는다.
- 저장된 프로필의 관심 분야는 목록의 '내 관심 분야만' 필터(F3-3)에 쓰인다. 기본 목록에는 적용하지 않는다 (Q-24). 닉네임 규칙은 Q-5.
- 진행: 조회·저장(온보딩) 완료.

**F1-4 토큰 재발급**
- OAuth 로그인 후 서비스 자체 JWT(Access/Refresh)를 발급한다.
- Access Token 만료 시 Refresh Token으로 재발급하고, 재발급 때 Refresh Token은 **회전**한다 (이전 것은 무효).
- 만료·위조·이미 회전된 토큰은 모두 401이다 (ADR-0002).

**F1-5 로그아웃**
- 서버에 저장된 Refresh Token을 삭제한다.
- 사용 중이던 Access Token은 만료 시점까지 블랙리스트로 처리해 그 사이에도 401을 반환한다.

**F1-8 회원 탈퇴**
- 계정과 개인 데이터(프로필, 북마크, 토큰 등)를 삭제하고 OAuth 제공자 연결을 해제(토큰 revoke)한다.
- 개인정보 수집 서비스는 탈퇴(동의 철회) 수단이 필요해 필수로 평가됨.
- revoke에 쓸 제공자 토큰은 탈퇴할 때 재인증으로 받는다. 재인증한 계정이 탈퇴하는 회원과 같아야 한다 (Q-25).
- revoke가 실패하면 탈퇴하지 않고 계정·데이터를 그대로 둔다 (Q-7).
- 탈퇴하면 모든 기기의 Access·Refresh가 401이다. 같은 계정으로 다시 로그인하면 새 회원이다.
- 진행: Google 완료(2026-11-12, 테스트). Kakao는 F1-6과 함께 남음.

**F2-1 대회 수집**
- 대회 사이트를 주기적으로 크롤링한다 (예: 하루 1회).
- 저장 필드: 제목, 주최, 분야(소스 태그 원문), 접수 기간, 대회 일정, 참가 URL. 참가 자격 원문은 주는 소스가 없어 저장하지 않는다 (Q-23).
- 실패하면 **기존 데이터를 유지**하고 로그를 남긴다. 한 소스의 실패가 다른 소스 결과를 막지 않는다.
- 수집한 대회마다 F2-2(중복 제거)와 F3-1(분야·형식 분류)이 이어서 적용된다.
- 참가 URL은 집계 사이트의 소개 페이지가 아니라 **공식 참가 페이지**다. 공식 참가 URL을 가져올 수 없는 소스는 쓰지 않는다 (Q-20). 포스터·썸네일 이미지는 수집하지 않는다.
- 진행: 소스는 Dev Event·DACON·Devpost(Q-1, Q-20)·이벤터스(Q-25)·코드포코리아(Q-26). 온오프믹스는 크롤러 차단으로 제외했다(Q-27). 매일 06:00 KST에 GitHub Actions가 수집을 실행한다(Q-21).

**F2-2 중복 제거**
- 여러 사이트에 올라온 같은 대회를 하나로 병합한다. 재크롤링해도 중복 생성되지 않는다(멱등).
- 같은 대회 기준: 같은 사이트의 같은 원문이거나, 다른 사이트에서 **제목이 겹치고**(정규화한 제목이 같거나, 짧은 쪽이 8자 이상이면서 다른 쪽에 포함) **공식 참가 URL 또는 마감일이 같다**. 주최는 사이트마다 표기가 달라 보지 않는다 (Q-2).
- 사이트별 원래 값은 출처마다 남기고, 보여 주는 값은 소스 우선순위로 고른다. 수집 순서와 상관없이 결과가 같다. 성공한 수집에서 빠진 출처는 묶음에서 뺀다 (Q-2).

**F2-3 대회 목록**
- 정렬: 마감 임박순(기본), 최신순. 페이지네이션 필수. 필터: 상태(접수 중/예정/마감). 제목 검색.
- **마감된 대회는 기본 목록에서 제외**한다. 상태 필터로 '마감'을 명시하면 볼 수 있다. 접수 마감 3일 뒤 삭제한다 (Q-3).
- 분야·형식 필터는 F3-3과 함께 적용된다.

**F2-4 대회 상세**
- 표시: 대회 정보, D-day, 분류된 분야·형식 태그. D-day는 KST 날짜 기준 접수 마감까지 남은 일수. 참가 자격(원문)은 주는 소스가 없어 표시하지 않는다 (Q-23). 같은 대회를 올린 사이트별 원문 링크, 정보 갱신 시각, 로그인 회원의 저장 여부를 함께 보여 준다 (Q-29).

**F2-5 참가 바로가기**
- 클릭 시 공식 참가 URL을 새 창으로 열고 서버는 클릭 수를 기록한다.
- 마감된 대회는 버튼을 비활성화하고, 서버도 마감 대회의 클릭 기록 요청을 거절한다. (가정) 마감 당일까지는 허용한다.
- 수집 때 공식 참가 URL을 못 가져온 대회도 버리지 않고 `apply_url: null`로 저장·노출한다. 프론트는 버튼 대신 "참가 링크를 찾지 못했어요. 대회 이름으로 직접 검색해서 찾아 주세요." 안내를 띄우고, 서버도 이 대회의 클릭 기록을 409 `APPLY_URL_MISSING`으로 거절한다 (Q-29).
- 다시 수집할 때 링크를 못 찾아도 이미 저장된 링크는 지우지 않고, 대표 소스에 링크가 없으면 같은 대회를 수집한 다른 소스의 링크로 채운다.
- 클릭은 로그인이 선택이고 누를 때마다 한 건씩 남긴다. 탈퇴(F1-8)하면 그 회원의 클릭도 지운다.

**F2-7 대회 저장(북마크)**
- 로그인 사용자가 대회를 저장·해제하고 내 저장 목록을 조회한다.
- 2차 알림(F4)의 대상이므로 `(user_id, contest_id)` 유일 제약과 저장 시각을 남긴다.
- 저장·해제는 멱등이다. 다시 저장해도 처음 저장 시각을 유지하고, 저장하지 않은 대회를 해제해도 성공이다.
- 없는 대회 저장은 404, 접수가 마감된 대회 저장은 409 `CONTEST_CLOSED`다 (Q-18). 마감 당일까지는 저장할 수 있다.
- 내 목록은 최근 저장순, 페이지네이션. 저장한 뒤 마감된 대회는 `closed`로 보이고, 삭제된 대회(Q-3)는 건너뛴다.

**F3-1 분야·형식 분류**
- 수집 시 대회마다 분야·형식 태그를 저장한다. 근거가 분명한 것만 붙이고, 없으면 그 차원은 `미분류`다 (Q-23).
- 분야(개발/AI/보안/디자인/아이디어, 프로필 관심 분야와 같은 어휘): 소스가 붙인 태그(Dev Event 태그, DACON 키워드, Devpost 테마, 이벤터스 세부 분야·태그, 코드포코리아 행사 주제)를 **대응표**로 옮긴다. 태그와 통째로 같아야 하고 부분 일치·본문 추측은 하지 않는다. 소스 자체가 분야를 정하면(DACON → AI, Devpost → 개발) 기본값으로 더한다.
- 형식(해커톤/경진대회/공모전/아이디어톤): **제목**에 형식 단어가 있으면 그 값, 없으면 소스 기본값(DACON → 경진대회, Devpost → 해커톤). '챌린지'·'대회'처럼 형식이 제각각인 단어로는 붙이지 않는다.
- 참가 자격(학력·참가 형태·지역)은 분류하지 않는다. 근거가 되는 원문을 주는 소스가 없다 (Q-23).
- 1차에서는 규칙을 설정 파일로 직접 관리한다 (관리 화면은 2차 F3-2). 규칙은 코드 분기가 아니라 데이터로 둔다.
- 진행: 완료. 규칙은 `app/contests/classification_rules.toml`. 2026-11-11 실데이터 기준 Devpost 81건은 분야·형식 모두, Dev Event 15건 중 분야 11건·형식 7건이 분류된다.

**F3-3 분야·형식 필터**
- 분야·형식을 **다중 선택**으로 필터링한다.
- 기본 목록은 프로필과 관계없이 마감되지 않은 대회 전체다. 로그인 회원은 '내 관심 분야만'(`interests=true`)을 켜서 프로필 관심 분야(F1-7)로 거를 수 있다 (Q-24).
- `미분류` 대회는 **제외하지 않고** '분류 확인 필요'로 함께 노출한다. 다중 태그 매칭 방식은 Q-9.
- 진행: 완료. `field`·`format`·`interests` 쿼리(ADR-0004).

## MVP에서 남길 확장 지점

- **F4-5/F4-6**: 크롤링 upsert 시 이전 값과 비교할 수 있는 구조를 유지한다. 접수 기간·일정은 별도 컬럼으로 두고, 덮어쓰기 전에 비교 가능한 서비스 함수로 분리한다.
- **F4-1/F4-2**: 알림 대상은 북마크(F2-7)다. 북마크에 생성 시각을 남기고, 시간 계산은 주입 가능한 `Clock` 포트로 한다.
- **F3-2**: 키워드 규칙은 코드가 아닌 데이터(테이블/설정 파일)로 둔다.
- **F3-4**: 프로필 필드(학년, 학교 유형, 관심 분야)는 태그 어휘와 같은 enum을 쓴다.
- **F6-4**: 태그에 출처(`rule` / `llm`) 컬럼을 둔다.
- **F2-6**: 참가 URL과 별개로 원문 페이지(`source_url`)를 보존한다.
