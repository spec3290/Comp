### 수용 기준

**F1-6 소셜 로그인**
- Google, Kakao OAuth2만 지원한다. ID·비밀번호 가입/로그인은 만들지 않는다 (ADR-0003).
- 최초 로그인 시 `provider + providerId`로 회원을 자동 생성하고, 이후에는 같은 키로 기존 회원을 조회한다.
- 성공하면 서비스 자체 JWT(Access/Refresh)를 발급한다 (F1-4).
- 신규 회원은 프로필 미설정 상태임을 응답으로 알 수 있어야 한다. (가정: `needs_onboarding`)

**F1-7 프로필 설정**
- 입력: 닉네임, 학년, 학교 유형, 관심 분야. 최초 OAuth 로그인 직후 온보딩에서 받는다.
- 저장된 프로필은 자격 필터(F3-3)의 기본값으로 쓰인다. 닉네임 규칙은 Q-5.

**F1-4 토큰 재발급**
- OAuth 로그인 후 서비스 자체 JWT(Access/Refresh)를 발급한다.
- Access Token 만료 시 Refresh Token으로 재발급하고, 재발급 때 Refresh Token은 **회전**한다 (이전 것은 무효).
- 만료·위조·이미 회전된 토큰은 모두 401이다 (ADR-0002).

**F1-5 로그아웃**
- 서버에 저장된 Refresh Token을 삭제한다.
- 사용 중이던 Access Token은 만료 시점까지 블랙리스트로 처리해 그 사이에도 401을 반환한다.

**F1-8 회원 탈퇴**
- 계정과 개인 데이터(프로필, 북마크, 토큰 등)를 삭제하고 OAuth 제공자 연결을 해제(토큰 revoke)한다.
- 개인정보 수집 서비스는 탈퇴(동의 철회) 수단이 필요해 필수로 평가됨. revoke 실패 시 동작은 Q-7.

**F2-1 대회 수집**
- 대회 사이트를 주기적으로 크롤링한다 (예: 하루 1회).
- 저장 필드: 제목, 주최, 분야, 접수 기간, 대회 일정, 참가 자격 원문, 참가 URL.
- 실패하면 **기존 데이터를 유지**하고 로그를 남긴다. 한 소스의 실패가 다른 소스 결과를 막지 않는다.
- 수집한 대회마다 F2-2(중복 제거)와 F3-1(자격 분류)이 이어서 적용된다.

**F2-2 중복 제거**
- 여러 사이트에 올라온 같은 대회를 하나로 병합한다. 기준은 **제목 + 주최 + 마감일**. 재크롤링해도 중복 생성되지 않는다(멱등).
- 제목 정규화와 대표 값 선택은 Q-2.

**F2-3 대회 목록**
- 정렬: 마감 임박순(기본), 최신순. 페이지네이션 필수. 필터: 분야, 상태(접수 중/예정/마감). 제목 검색.
- **마감된 대회는 기본 목록에서 제외**한다. 상태 필터로 '마감'을 명시하면 볼 수 있다. (가정, Q-3)
- 자격 필터는 F3-3과 함께 적용된다.

**F2-4 대회 상세**
- 표시: 대회 정보, 참가 자격(원문), D-day, 분류된 자격 태그. D-day는 KST 날짜 기준 접수 마감까지 남은 일수.

**F2-5 참가 바로가기**
- 클릭 시 공식 참가 URL을 새 창으로 열고 서버는 클릭 수를 기록한다.
- 마감된 대회는 버튼을 비활성화하고, 서버도 마감 대회의 클릭 기록 요청을 거절한다. (가정)

**F2-7 대회 저장(북마크)**
- 로그인 사용자가 대회를 저장·해제하고 내 저장 목록을 조회한다.
- 2차 알림(F4)의 대상이므로 `(user_id, contest_id)` 유일 제약과 저장 시각을 남긴다.

**F3-1 자격 분류**
- 수집 시 참가 자격 원문에 **키워드 규칙**을 적용해 태그를 저장한다.
- 태그 차원: 학력(고등학생/대학생/제한 없음), 참가 형태(개인/팀), 분야(개발·AI·보안·디자인·아이디어), 지역(전국/특정 지역). 매칭이 없으면 `미분류`.
- 1차에서는 규칙을 DB 또는 설정 파일로 직접 관리한다 (관리 화면은 2차 F3-2). 규칙은 코드 분기가 아니라 데이터로 둔다.

**F3-3 자격 필터**
- 학력·참가 형태·분야·지역을 **다중 선택**으로 필터링한다. 기본값은 프로필(F1-7).
- `미분류` 대회는 **제외하지 않고** '자격 확인 필요'로 함께 노출한다. 다중 태그 매칭 방식은 Q-9.

## MVP에서 남길 확장 지점

- **F4-5/F4-6**: 크롤링 upsert 시 이전 값과 비교할 수 있는 구조를 유지한다. 접수 기간·일정은 별도 컬럼으로 두고, 덮어쓰기 전에 비교 가능한 서비스 함수로 분리한다.
- **F4-1/F4-2**: 알림 대상은 북마크(F2-7)다. 북마크에 생성 시각을 남기고, 시간 계산은 주입 가능한 `Clock` 포트로 한다.
- **F3-2**: 키워드 규칙은 코드가 아닌 데이터(테이블/설정 파일)로 둔다.
- **F3-4**: 프로필 필드(학년, 학교 유형, 관심 분야)는 태그 어휘와 같은 enum을 쓴다.
- **F6-4**: 태그에 출처(`rule` / `llm`) 컬럼을 둔다.
- **F2-6**: 참가 URL과 별개로 원문 페이지(`source_url`)를 보존한다.
